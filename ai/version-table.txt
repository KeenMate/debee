VERSION TABLE
=============

CRITICAL: The prepareVersionTable operation generates documentation of all database
objects found across migration and ad-hoc scripts.

OVERVIEW
--------
Debee scans SQL files, extracts database objects (tables, functions, views, indexes,
triggers, schemas), and produces a tracking report with complete change history.

Running:
  ./debee.sh -o prepareVersionTable
  python debee.py -o prepareVersionTable
  .\debee.ps1 -Operations prepareVersionTable

OUTPUT FORMATS
--------------
Configured via DBVERSIONTABLEFORMATS env var (semicolon-separated):

  DBVERSIONTABLEFORMATS=html;json;md;csv

Format    Output File          Description
json      db-objects.json      Machine-readable, full object details and history
md        db-objects.md        Markdown table for documentation
csv       db-objects.csv       Spreadsheet-compatible format
html      db-objects.html      Interactive dashboard with filtering

Output location: DBVERSIONTABLEOUTPUTFOLDER (default: .)
Base filename: DBVERSIONTABLEFILENAME (default: db-objects)

WHAT GETS TRACKED
-----------------

Object Types:
  - Tables (including UNLOGGED and TEMPORARY)
  - Functions and Procedures
  - Indexes (including UNIQUE and CONCURRENT)
  - Views
  - Triggers
  - Schemas

Operations Tracked:
  - CREATE
  - CREATE OR REPLACE
  - ALTER
  - DROP (with IF EXISTS support)

Per-Object Information:
  - Schema and object name
  - Object type
  - Last update file and line number
  - Last operation type
  - Total update count
  - Complete update history with file references
  - Source classification (Migration vs Ad-hoc)

EXTRACT-DB-OBJECTS.PY
---------------------
The Python script that does the actual SQL parsing.

Features:
  - Scans migration files following XXX_*.sql pattern
  - Scans ad-hoc scripts directory (if DBADHOCDIRECTORY set)
  - Supports schema-qualified object names
  - Encoding fallback: UTF-8 → Latin-1
  - Summary statistics by object type and schema
  - No external dependencies (standard library only)

The orchestrators call this script automatically during prepareVersionTable.

Direct usage:
  python extract-db-objects.py --format markdown
  python extract-db-objects.py --format json --output db-objects.json
  DBADHOCDIRECTORY=hotfix-scripts/ python extract-db-objects.py --format html

Parameters:
  --format    Output format: json, csv, markdown, html (default: json)
  --output    Output file path (default: stdout)

HTML INTERACTIVE DASHBOARD
--------------------------
Single self-contained HTML file with embedded CSS and JavaScript.

Features:
  - 8 independent filter controls (schema, name, type, operation, file,
    migrations, ad-hoc, update count)
  - Click-to-filter: click any schema, object name, or file to filter
  - Responsive design: desktop table view, mobile card layout
  - Local storage: layout preferences persist across sessions
  - Conditional ad-hoc columns: hidden when no ad-hoc data exists
  - Color-coded object type badges
  - File:Line:Operation format for precise change tracking
  - Real-time statistics (filtered vs total counts)

Responsive breakpoints:
  Desktop (1200px+):  Full table, 4-column filter grid
  Laptop (992-1199):  Table, 3-column filter grid
  Tablet (768-991):   Table, 2-column filter grid
  Mobile (<768px):    Card layout, single-column filters

Template: version_table_template.html
  - Uses data placeholders filled during generation
  - Located in postgresql/ directory

AD-HOC SCRIPT TRACKING
-----------------------
When DBADHOCDIRECTORY is configured:
  - Dedicated "Source" column: "Migration" vs "Ad-hoc"
  - Separate update counts for migration and ad-hoc changes
  - All output formats support source classification
  - No naming convention required for ad-hoc files
  - Any .sql file in the directory is processed recursively
